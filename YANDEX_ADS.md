# Яндекс Реклама — Unity / Android

## Подключение

В `Packages/manifest.json` добавлен официальный **Yandex Mobile Ads Unity plugin 8.6.0**, закреплённый на commit `2b5c0650918e003c06038e7738db698e0a0f428f` репозитория `yandexmobile/yandex-ads-unity-plugin`, подпапка `mobileads-sdk`. Реестр OpenUPM нужен для объявленных плагином зависимостей `com.google.external-dependency-manager` 1.2.178 и `com.yandex.mobileads.appmetrica.adrevenue.adapter` 1.0.0. Исходники/бинарники SDK не скопированы в Assets и не заменены заглушками.

При первом открытии Unity скачает пакеты и пересоздаст `Packages/packages-lock.json`. В облаке UPM-импорт и Android dependency resolution не выполнялись: нет активированного Unity, Android Build Support и разрешения сети к OpenUPM. Старый lock-файл намеренно не подделывался вручную. На компьютере разработчика нужны доступ к GitHub/OpenUPM/Maven и установленный Git.

Это **базовый SDK Яндекса**, а не полный набор адаптеров всех сетей медиации. Присланная строка `implementation 'com.yandex.ads.mediation:mobileads:8.6.0'` относится к Android-подключению полного пакета медиации. Здесь Gradle-зависимости базового SDK задаёт официальный Unity-плагин через EDM4U: вручную дублировать эту строку не нужно. Если понадобится медиация других сетей, их адаптеры и настройки добавляются отдельно.

Источники API: официальный [репозиторий и инструкция установки](https://github.com/yandexmobile/yandex-ads-unity-plugin), примеры `samples/YandexMobileAdsBannerDemoScript.cs` и `samples/YandexMobileAdsInterstitialDemoScript.cs` закреплённой версии. Страница `ads.yandex.com` недоступна из облака из-за сетевой политики; код проверен по исходникам официального плагина.

## Настройки и идентификаторы

Откройте `Assets/Resources/YandexAdsSettings.asset` в Inspector.

| Поле | Значение |
| --- | --- |
| Application Id | `20344040` |
| Banner Id | `R-M-20344040-1` |
| Interstitial Id | `R-M-20344040-2` |
| Test Mode | включён |

Application Id сохранён для справки: загрузка объявлений в этом API выполняется по ID блока, это число не является Android package name или ключом AppMetrica.

**Тестовые объявления включены по умолчанию.** В Development Build они используются всегда, даже при выключенном Test Mode. Запросы используют официальные `demo-banner-yandex` и `demo-interstitial-yandex`. Для коммерческого релиза выключите Test Mode в asset и собирайте обычный APK с выключенным Development Build. Не проверяйте клики на собственных боевых объявлениях.

Перед запросами вызываются `SetUserConsent(false)` и `SetLocationTracking(false)`: приложение не выдаёт согласие пользователя за него и не включает геолокацию. Возраст пользователя не предполагается. Это не полноценный интерфейс согласия; при добавлении персонализации нужно передавать реальный выбор пользователя. SDK подключает свои зависимости AppMetrica/ad-revenue; отдельный ключ аналитики приложение не выдумывает.

## Места показа

- **Баннер**: Sticky / BottomCenter, только основное меню. Ширина рассчитывается по симметричному безопасному отступу экрана, высота — по SDK. Меню оставляет под него место. При повороте/смене safe area баннер пересоздаётся; при открытии настроек/подтверждения скрывается, при начале игры уничтожается.
- **Межстраничная реклама**: заранее загружается и используется после поражения, когда игрок нажал «Ещё раз» либо «В меню» (включая Android Back на экране Game Over). Результат сначала остаётся видимым. Во время игры, обычной паузы, добровольного перезапуска незавершённой партии и обучения полноэкранных показов нет.
- Первая завершённая обычная партия проходит без межстраничной рекламы. Начиная со второй разрешён один показ в естественной точке перехода, не чаще раза в 120 секунд. Счётчик партий и время **фактического** показа сохраняются между запусками; неуспешная загрузка не расходует интервал.
- Если реклама не готова или нет сети, переход выполняется сразу. После закрытия/ошибки показа переход выполняется один раз. Во время показа игровой звук приостановлен; после завершения возвращается прежнее состояние.
- Ошибки загрузки не вызывают цикл запросов каждый кадр: повторная попытка не раньше 30 секунд. Есть отмена зависшей загрузки, защита от устаревших callbacks, срок хранения подготовленного interstitial и защитный таймер до подтверждённого открытия.

## Проверка

1. Обновить проект целиком и дождаться Package Manager/компиляции. В Package Manager должна появиться версия Yandex Mobile Ads 8.6.0, EDM4U и ad-revenue adapter. При ошибке разрешения пакетов сначала исправить её; не удалять зависимости SDK из asmdef.
2. Выбрать Android / Switch Platform. Выполнить **Assets → External Dependency Manager → Android Resolver → Force Resolve**. Resolver должен подключить Android-зависимости; Gradle-шаблоны, ранее отключённые в проекте, вслепую не возвращать.
3. Собрать Development APK через **Tools → Block Blast → Build Android Development APK**. В Unity Editor реальные объявления не показываются: Android-адаптер намеренно выключен, переходы работают без рекламы.
4. На телефоне проверить тестовый баннер в меню, его отсутствие в настройках и игре; проверить portrait/landscape и Pixel safe area, отсутствие перекрытия «Играть»/«Новая игра».
5. Завершить первую обычную партию: реклама не появляется. После второй — нажать «Ещё раз»/«В меню», закрыть объявление, проверить ровно один переход и звук. Повторить раньше 120 секунд: нового полноэкранного показа быть не должно.
6. Проверить авиарежим/ошибку загрузки: меню и завершение партии не блокируются; позже загрузка возобновляется. Проверить закрытие/сворачивание рекламы и возврат приложения, отсутствие неожиданного позднего показа.
7. Пройти повторное обучение, проверить паузу, обычный перезапуск и продолжение сохранённой партии: реклама не должна появляться в этих переходах. Установка обновления APK поверх прежней должна сохранять партию/рекорд.

Проверено в облаке: **104 теста модели** прошли, в том числе ограничения первой партии, интервала, перезапуска и перевода часов назад. Код Android-адаптера компилируется против реальных публичных C# API SDK 8.6.0 (исходники с официальным dummy backend используются только для проверки сигнатур вне Unity); Unity-тесты компилируются. Это не проверка настоящего Android backend: APK, Gradle/EDM4U, JNI, фактические показы, callback-последовательность и раскладка на телефоне здесь не выполнялись.
